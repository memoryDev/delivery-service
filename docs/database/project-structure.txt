# 📁 패키지 구조 & 도메인 설명

---

## 전체 구조

```
com.delivery.app
├── domain/       # 비즈니스 기능 모음
└── global/       # 전체 공통 설정 모음
```

---

## domain/ — 비즈니스 기능 모음

기능별로 패키지를 나눈 **도메인형 구조**입니다.  
`user`, `restaurant`, `order` 등 핵심 기능들이 각자 독립적인 폴더를 가집니다.

```
domain/
├── user/
├── restaurant/
├── menu/
├── order/
├── payment/
├── review/
└── rider/
```

각 도메인 내부는 아래와 같이 역할이 나뉩니다.

| 폴더 | 역할 | 설명 |
|---|---|---|
| `controller` | 요청 창구 | 클라이언트 요청을 받는 곳. `@RestController` 클래스가 위치합니다. |
| `service` | 비즈니스 로직 | 실제 핵심 로직이 실행되는 곳. 주문 생성, 결제 처리 등을 담당합니다. |
| `repository` | DB 통신 | JPA Repository + QueryDSL 코드가 위치합니다. |
| `entity` | DB 테이블 매핑 | ERD에서 설계한 테이블들이 Java 클래스로 표현되는 곳입니다. |
| `dto/request` | 요청 데이터 형식 | 클라이언트 → 서버로 전달되는 데이터 형식입니다. (예: 회원가입 시 이메일/비밀번호) |
| `dto/response` | 응답 데이터 형식 | 서버 → 클라이언트로 반환되는 데이터 형식입니다. (예: 주문 조회 결과) |

---

## global/ — 전체 공통 설정 모음

특정 도메인에 속하지 않고 **프로젝트 전체에서 공통으로 사용되는 요소**들이 위치합니다.

```
global/
├── config/
├── exception/
├── response/
├── security/
└── util/
```

| 폴더 | 역할 | 설명 |
|---|---|---|
| `config` | 설정 클래스 | Spring Security, Redis, Swagger 등 설정을 담당합니다. |
| `exception` | 공통 예외 처리 | `@RestControllerAdvice`로 에러 응답을 한 곳에서 관리합니다. |
| `response` | 공통 응답 형식 | 모든 API가 공통으로 사용하는 `ApiResponse<T>`가 위치합니다. |
| `security` | 인증/인가 | JWT 토큰 생성/검증, 인증 필터 클래스들이 위치합니다. |
| `util` | 유틸리티 | 날짜 변환, 암호화 등 여러 곳에서 사용하는 공통 클래스들입니다. |

## 각 도메인 상세 설명

### 👤 user — 일반 고객
배달 앱을 사용하는 **일반 사용자** 도메인입니다.

- 회원가입 / 로그인
- 내 주문 내역 조회
- 리뷰 작성
- JWT 토큰 기반 인증

---

### 🏪 restaurant — 음식점
**음식점 사장님**이 운영하는 가게 정보 도메인입니다.

- 음식점 등록 / 수정 / 삭제
- 영업 상태 관리 (오픈 / 마감)
- 음식점 목록 조회 (카테고리, 평점 필터)
- 주문 수락 / 거절

---

### 🍔 menu — 메뉴
음식점에 속한 **음식 메뉴** 정보 도메인입니다.

- 메뉴 등록 / 수정 / 삭제
- 품절 처리 (AVAILABLE / SOLD_OUT)
- 음식점별 메뉴 목록 조회
- 메뉴 가격 관리

---

### 📦 order — 주문
고객이 음식을 **주문하는 핵심 도메인**입니다. 가장 복잡한 비즈니스 로직을 포함합니다.

- 주문 생성 (장바구니 → 주문)
- 주문 상태 관리
  ```
  PENDING → ACCEPTED → COOKING → DELIVERING → DELIVERED
                ↓
           CANCELLED
  ```
- 주문 내역 조회
- 주문 취소

---

### 💳 payment — 결제
Portone(아임포트) 연동 **결제 도메인**입니다.

- 결제 요청 / 검증
- 결제 금액 위변조 검증 (서버 사이드)
- 결제 취소 (환불)
- 결제 수단 관리 (카드 / 카카오페이 / 네이버페이 / 토스)

---

### ⭐ review — 리뷰/평점
주문 완료 후 작성하는 **리뷰 도메인**입니다.

- 리뷰 작성 (배달 완료된 주문만 가능)
- 별점 1~5점
- 리뷰 수정 / 삭제
- 음식점 평균 평점 자동 반영

---

### 🛵 rider — 배달원
음식을 **배달하는 라이더 도메인**입니다.

- 라이더 등록 (User 계정과 연결)
- 배달 가능 상태 관리 (AVAILABLE / DELIVERING / OFF)
- 주문 배달 수락
- Firebase FCM 토큰 관리 → 푸시 알림 수신

---

## 도메인 간 관계 요약

```
User ────────── 주문 생성 ──────────▶ Order
                                        │
Restaurant ◀─── 주문 수신              │
     │                                  │
Menu ──────────── 주문 항목 ──────────▶ OrderItem
                                        │
Rider ◀──────── 배달 배정              │
                                        │
Payment ◀────── 결제 연결 ────────────┘
                    │
Review ◀─────── 완료 후 작성
```

---

## 한줄 요약

| 도메인 | 한줄 요약 |
|---|---|
| `user` | 앱을 사용하는 고객 |
| `restaurant` | 음식점 사장님과 가게 정보 |
| `menu` | 음식점의 음식 메뉴 |
| `order` | 주문 생성과 상태 흐름 |
| `payment` | Portone 연동 결제 |
| `review` | 주문 완료 후 리뷰/평점 |
| `rider` | 배달원과 FCM 푸시 알림 |
